# Security Policy

## Supported Versions

Security fixes are handled on the `main` branch before the next tagged release. Released packages should be upgraded to the newest available version once a fix is published.

## Reporting A Vulnerability

Use GitHub private vulnerability reporting if it is enabled for the repository. If private reporting is not available, open a minimal public issue asking for a private contact path and do not include exploit details, secrets, or weaponized proof of concept material in the public issue.

Please include:

- Affected version or commit.
- Impacted API, control, or demo surface.
- Minimal reproduction steps.
- Expected and actual behavior.
- Any relevant OS, .NET SDK, and Windows version details.
