## Review Focus

These five conditions drove the original probe. The first phase covered only the recorded 150% DPI, probe-only topmost acquisition and selected live checks. Windows 10, RDP, OS High Contrast, 100% DPI first show, ordinary non-topmost activation, and several native caption/taskbar interactions remain open.

1. A DWM attribute query fails: Task 3 records failure and Task 4 refuses to treat a default value as success.
2. A backdrop is unavailable in RDP, High Contrast, or Windows 10: Task 4 records each available branch and marks unavailable branches unverified.
3. A first-frame flash lasts less than a sampled frame: Task 4 records fixed-region compositor capture cadence and does not claim a pass from a missed frame.
4. `WindowChrome` and WPF Fluent backdrop both write the same HWND: Task 3 logs the mode and pre-show checkpoints; Task 4 compares fresh processes without assuming writer ownership from a final value.
5. `None` or a live theme swap turns the surface opaque: Task 4 observes None, Light to Dark to Light, and High Contrast in one window before proposing any target-clear change.

### Task 3: Add an opt-in standalone window probe

**Recorded status:** Complete in `d82b131a` and the private first-phase review. The probe was built on three targets, checked for valid/invalid CLI invocations, used in the bounded acquisition, and kept outside the library package and solution. The original instruction to enter OS High Contrast was an observation request for Task 4, not a completed host check. Recorded observations must still be read with the limits in Task 4.

**Files:** Create `tools/Fluence.WindowProbe/Fluence.WindowProbe.csproj`, `Program.cs`, `ProbeOptions.cs`, `ProbeWindowFactory.cs`, `NativeSnapshot.cs`, `ProbeRecord.cs`, and `README.md`. Do not add the project to `Fluence.Wpf.sln`, the package, or CI. Reference only `Fluence.Wpf/Fluence.Wpf.csproj` through `ProjectReference`.

**Interfaces:** `ProbeOptions.Parse(string[] args)` lives in `ProbeOptions.cs` and accepts `--mode plain|chrome-dwm|fluence|wpf-fluent`, `--theme Light|Dark`, `--render-mode default|software-only`, `--size fixed|content`, and `--output absolute-path`. `--backdrop None|Mica|Acrylic|Tabbed` is accepted only for `chrome-dwm` and `fluence`; `plain` and `wpf-fluent` reject it and report requested backdrop as N/A. The `chrome-dwm` mode additionally accepts `--explicit-target-clear on|off`, `--full-glass on|off`, `--dwm-attribute on|off`, and `--force-target-opaque on|off`; other modes reject these switches. An absent `--explicit-target-clear` leaves `WindowChrome` free to clear the target, whereas `--force-target-opaque` overwrites the target after chrome initialization for a diagnostic contrast. Invalid combinations exit nonzero with usage. `ProbeOptions.Parse` and setting `RenderOptions.ProcessRenderMode` from the selected mode run in a fresh process before `Application`, theme resources, or any HWND; log both that preference and the actual `RenderCapability.Tier`. `ProbeWindowFactory.Create(ProbeOptions)` returns a fresh `Window` with buttons `Next theme`, `Next backdrop`, and `Grow content`; inapplicable actions are visibly disabled. Construct `NativeSnapshot` in `NativeSnapshot.cs` with `(ProbeOptions options, Window window)`, then call its `ProbeRecord Capture(IntPtr hwnd, string phase)` method; `ProbeRecord` lives in `ProbeRecord.cs`. `ProbeRecord` is a `[DataContract]` containing `[DataMember]` strings or numbers for UTC timestamp, phase, mode, requested theme/backdrop or N/A, requested render mode and actual render tier, actual WPF and target colors, HWND style/rectangle, DPI, OS/runtime/session, DWM backdrop/corner/cloak values, individual query HRESULTs, and direct probe-owned call HRESULTs. `Program` serializes each record with built-in `DataContractJsonSerializer` to newline-delimited JSON at the requested path; it never fills a failed query with a successful default.
